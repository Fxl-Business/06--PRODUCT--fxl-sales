### The five isolation mechanisms, all implemented

1. `orgId` is a required positional parameter; the module exports exactly one read and has no unscoped variant.
2. Fail-closed: `if (typeof orgId !== 'string' || orgId.trim() === '') throw new Error('org_id_required');` is the first statement.
3. `const conditions: SQL[] = [eq(auditLog.actorOrgId, orgId)];` - the scope predicate is the array literal's first element; optional filters are `push`ed after it.
4. The module never imports the admin connection factory, pinned by a source-reading assertion in `history-route.test.ts`.
   The doc comment had to be reworded to avoid naming the symbol in prose, because the guard reads the whole file - which is the guard working as designed.
5. The org can only come from the verified token: `HistoryQuerySchema` declares no org key, and the oracle plus the route test both smuggle `?orgId=` / `?actorOrgId=` and assert the result is unchanged.

## Deviations from the plan

One, and it is a correction rather than a design change.

**The actor-name map is keyed by `audit_log.id`, not by `entity_id`.** The plan's section 4.3 describes the resolution chain but not the map key; keying it by `entity_id` would collide the moment one cadastro is archived and later restored - which is the exact traffic this feature generates - and could attribute the restore to the archiver. `resolveActorNames` returns `Map<bigint, string>` keyed by the ledger row id.

Everything else follows the plan verbatim, including `limit + 1` fetching, the two named `->>` scalar extractions with no blob select, `String(row.id)` projection, `HISTORY_DEFAULT_LIMIT = 50` / `HISTORY_MAX_LIMIT = 200`, the `?.length` guard against `inArray(..., [])`, the transaction with the comment stating it buys nothing for `audit_log`, and the `action` set / `entityType` equality asymmetry.

## Migration

`drizzle-kit generate --name audit_log_org_history_idx` picked `0019`, as the plan predicted. Contents, unmodified:

```sql
CREATE INDEX "audit_log_actor_org_id_id_idx" ON "audit_log" USING btree ("actor_org_id","id" DESC NULLS LAST) WHERE "audit_log"."actor_org_id" IS NOT NULL;
```

No `-- fxl-migration-mode: phased` header, no `CONCURRENTLY`. Journal entry appended by the tool as `{"idx": 19, ..., "tag": "0019_audit_log_org_history_idx"}`.

Applied to the **local Docker** DB by the integration suite's `globalSetup` (`localhost:5006`). `apps/api/.env`'s staging `DATABASE_URL` was never used. Verified in the container:
