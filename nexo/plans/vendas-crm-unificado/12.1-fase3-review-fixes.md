# 12.1 Phase 3 review fixes and the stage_changed_at clock flake

Sources: `nexo/runs/20261021T011348Z-vendas-crm-unificado/agents/review-phase3-r1/findings.json` (R1-1 major, R1-2 minor, R1-3 minor) and the phase 3 wave suite failure.
Affected tests search: the shell oracle and `leads-move-concurrency.test.ts` are the owners; no other test asserts these behaviours.

1. R1-1 (`SalesOpsApp.tsx` ~1811): gate the header "Nova proposta" action (and any other create-proposta entry on non-proposta views) on the `orcamentos` module (`modulesAllowCapability(modules, 'proposals')`). Test in `org-modules-shell.test.tsx`: modules `orcamentos=false, comissoes=true`, route `/operacional/comissoes`: no `Nova proposta` button; with orcamentos on it is there.
2. R1-2 (`SalesOpsApp.tsx` ~2069): the commission balance card uses `modulesAllowCapability(modules, 'commissions')` instead of `hasCapability(edition, 'commissions')`. Test both combinations.
3. R1-3: add the shell/board-level test: with `orcamentos` off, moving a lead onto the `Proposta` (type `orcamento`) stage through the non-drag path (`Mover` in the Lista view or the `MoveLeadDialog`) calls the lead move mutation and never requests conversion (no proposta wizard); with `orcamentos` on the same action requests conversion. Do not mock `LeadsBoardContainer` away in this test (mock only the API layer, like `leads-stage-navigation.test.tsx` does). If driving the real container is impossible in happy-dom, test the container (`LeadsBoardContainer`) directly with the modules context provider and say so.
4. Clock flake: `apps/api/test/rls/leads-move-concurrency.test.ts:245` fails intermittently because a stage change writes `stage_changed_at` from the Node clock (`new Date()`, millisecond precision, e.g. `...857000` µs) while lead creation uses the database `now()`; when the database clock is ahead of Node's the later move stamps an EARLIER instant. Fix the product code: every write of `stage_changed_at` on a stage change (lead-service move, advance in `lead-history-service.ts`, restore in `lead-trash-service.ts`, and any other writer you find with `grep -rn "stageChangedAt" apps/api/src`) uses the database clock (`sql\`now()\``) like the create path. Do not touch the test's assertion. Prove it: run `pnpm --filter @fxl-sales/api exec env VITEST_INTEGRATION=1 vitest run test/rls/leads-move-concurrency.test.ts` 10 times in a row, all green; also run the history oracle `test/rls/crm-pipeline-history.test.ts`.
5. Commits: `fix(web): gate the Nova proposta action on orcamentos`, `fix(web): commission card follows the comissoes module`, `test(web): moving onto Proposta with orcamentos off never converts`, `fix(crm): stamp stage_changed_at with the database clock`.
