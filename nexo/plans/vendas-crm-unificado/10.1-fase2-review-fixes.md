Test: an org with the default pipeline plus a second active non-default pipeline whose position sorts first; creating a lead with no `pipelineId` lands in the DEFAULT pipeline, and `GET /lead-stages` without `pipelineId` returns the default pipeline's stages.

Test: archive a stage that has no edges (create it archived through the migration fixture or by inserting it and deleting nothing: simplest is to create a stage, delete nothing, but insert it with status archived via the admin connection), restore it through `PATCH /lead-stages/:id`, then move a lead into it and out of it: both 200.

R1-04 (`lead-history-service.ts` ~406, `markFollowupDone`): authorize completion when the caller is an admin, OR the caller's pessoa is the follow-up's `owner_person_id`, OR the caller may access the lead under the seller scope (as today). R1-03 (`apps/web/src/sales-ops/leads/lead-form.ts` ~251, `leadToWriteSeed`/undo path): when the lead being restored has no contact (both phone and email null), OMIT `contactPhone` and `contactEmail` from the undo PATCH exactly like the normal edit does. ## Round 2 (Codex review round 2, R2-01)

Evidence: `nexo/runs/20261021T011348Z-vendas-crm-unificado/agents/review-phase2-r2/findings.json`. Editing a contactless legacy lead to ADD its first contact and then clicking Desfazer keeps the added contact, silently, because the undo omits the contact keys and the API cannot clear the only contact (`contact_required`).
Fix (in `LeadSummaryContainer` / the summary edit-undo path, wherever the undo notice is published for an edit):
1. Test first (in `apps/web/src/sales-ops/leads/__tests__/lead-summary-container.test.tsx`): edit a lead whose `contactPhone` and `contactEmail` are both null, add a phone, save: NO `Desfazer` notice is offered (the save still succeeds). Keep the existing test where an edit that stays contactless still offers an undo that omits the contact keys.
2. Code: publish the edit undo only when the inverse is complete: if the previous lead had no contact and the saved lead has one, do not publish the undo notice.
3. Document it in `nexo/knowledge/reference/kanban-de-leads.md` (section "Phase 2 review fixes"): an edit that gives a contactless lead its first contact offers no undo.
Commit `fix(web): no undo when an edit adds a contactless lead's first contact`.
