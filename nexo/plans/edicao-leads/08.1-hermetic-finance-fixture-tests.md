# 08.1 Hermetic finance fixture tests

Inserted during Execute (replan 1) after the wave 3 verify failed.

## Diagnosis (measured)

The dev seed (`apps/api/scripts/seed-dev.ts`) writes 4 sales and 6 leads for every roster org, including `org_fake_integrado` (`FIXTURE_INTEGRATED_ORGANIZATION_ID`).
The local dev database and the integration test database are the same database (`localhost:5006/fxl_sales`).
`finance-integration.integration.test.ts` must use that exact org, because the fake integration authority only activates it.
It cleans the org only in `afterEach`, deletes sales but not the leads whose `sale_id` references them (`sales_ops_leads_org_sale_fk`), and never cleans before the first test.
After a dev seed, its inserts collide on the unique `(org_id, sequence)` and its cleanup fails on the lead FK.
This is a pre-existing isolation defect; slice 08 only exposed it by running the seed.
`consumer.integration.test.ts` (3 failures) and one run of `test/rls/conversion-ingest.test.ts` also failed in the same verify run; diagnose them first and fix their cause too if it is the same pollution, or record the true cause in the commit message if not.

## Steps

1. Reproduce: run `pnpm --filter @fxl-sales/api db:seed:dev` (local only), then `pnpm --filter @fxl-sales/api test:integration` and record the failing tests (expect the finance-integration and consumer failures).
2. Add a test-only helper beside `deleteSettlementsForOrgs` in `apps/api/src/db/__tests__/settlement-test-cleanup.ts`: `purgeOrgLedgerForTests(orgIds)` that, using the same local superuser path, deletes for those orgs in FK-safe order: settlements (replica role), `sales_ops_lead_products`, `sales_ops_leads` (or sets their `sale_id` to null first if deleting leads is not possible), payables, receivables, sale professionals, sale items, sales, `integration_outbox`, `integration_inbox`, `integration_cursor`.
   Inspect `apps/api/src/db/schema.ts` for every table with an FK to `sales_ops_sales` and include it.
   Keep it test-only with the same superuser guard and doc comment style.
3. In `finance-integration.integration.test.ts`, call the helper for `[FIX]` in `beforeAll` (before any test) and in `afterEach`, replacing the hand-written delete list.
4. Apply the same fix to `consumer.integration.test.ts` only if step 1 shows its failures come from the same pollution.
5. Prove it: seed, run `test:integration` (full) twice, both green.
   Then also run it once more WITHOUT reseeding to prove nothing depends on seeded rows.
6. Never use the em dash; run-once commands only; no product code changes.
